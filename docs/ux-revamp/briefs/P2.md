## Goal
The student hears the exact moment behind a sentence: click a segment to hear it, see which segment is playing, keep the player in view while reading a long transcript. This runs on the run that just finished (the audio blob is in the run record). Opening a saved class later is milestone P3, so build the attach function generally.

## Facts you must respect (P0, DL4, DL5)
- Segment times are absolute: `chunk.startMs + segment.start*1000`, valid within about 0.01 s median (`sf.transcript.get().segments`, each with `startMs`, `endMs`, `text`, gap entries).
- Chrome MediaRecorder WebM reports `audio.duration === Infinity`. The seek bar and the "elapsed / total" MUST use the stored duration (`record.durationExactSec` when present, else `record.durationSec`), never the element's. Seeking by `currentTime` works for a 16 minute Chrome recording (measured, 1 to 16 ms).
- The audio is in `RunStore.getRun(runId).audioBlob` (original format: uploads keep the file, recordings the recorder's real type).

## Build
1. `app/static/js/player/transcript-player.js` (new) and `app/static/css/player.css` additions: `sf.transcriptPlayer.attach({blob, durationSec})` / `detach()`. It mounts `sf.player.create(blob, {durationSec})` into a docked container (`position: sticky` or fixed at the bottom of the viewport while the reading view is on screen, at 1280 and 375; the page bottom gets padding so the last rows are never covered; it must coexist with the sticky search toolbar at 375). Live hook: on `run:end` for a complete or partial run, fetch the record with `RunStore.getRun(runId)` and attach; on a new run or "Empezar otra clase", detach and revoke object URLs.
2. Segment interaction (in `reader.js`, via a hook that only exists once a player is attached): each timestamp becomes a `<button class="sf-segment__time">` with accessible name "Reproducir desde 00:31:05"; clicking the button OR the segment text seeks to `startMs/1000` and plays. Before a player exists timestamps stay plain `<time>` (no dead controls).
3. Current segment: while playing, the segment containing the current time (binary search over the sorted segments, updated at most once per animation frame) gets `aria-current="true"` and a visible state (left bar and panel background from tokens, NOT yellow; also a small play icon next to the time so it is not colour-only). Gap rows never get the state; their text becomes "Falta el texto de los minutos MM:SS a MM:SS. El audio de este tramo sí se puede escuchar." ONLY while a player is attached.
4. "Seguir" toggle (button with `aria-pressed`, default on): keeps the current segment in view (scrollIntoView block center, no smooth behaviour under `prefers-reduced-motion`), only when the current segment changes; it pauses automatically when the user scrolls manually (wheel, touch, keyboard scrolling not caused by our own scroll) and the toggle then shows the paused state and can be switched back on. Announce state changes politely once, never per tick.
5. Keyboard: Space toggles play/pause and ArrowLeft/ArrowRight skip 10 seconds ONLY when focus is not in a text field, select, textarea, contenteditable, and not on a button, link or `summary` (so Space on a focused button still activates it). All player controls are reachable by Tab, labelled, 44 px (timestamps may be 28 px, DL11), visible focus. Expose the shortcuts with `aria-keyshortcuts` and a short text in the player's help.
6. Mobile toolbar polish (decision made by the lead, DL46): in the sticky search toolbar, Copiar and Exportar become icon-only at 40rem and below, with `aria-label` ("Copiar transcripción", "Exportar .txt") and a `title`; icons `copy` and `download` already exist in `app/static/icons.svg`.
7. Only tokens and `sf-` components; new icons only through `tools/ux/build_icons.mjs`.
