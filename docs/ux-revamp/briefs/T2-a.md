## Why this step exists
The transcript view (next step, T2-b) will show fine-grained Whisper segments with real timestamps, as in `docs/ux-revamp/directions/A/transcript.html`. Today the UI shows one block per 5 minute chunk, built by the legacy appender in `app/static/js/transcript/segment.js`, and copy/export read `#transcript.textContent` (`js/transcript/view.js`), which bakes in English labels ("Segment 1/1") and badge text. The user decided (2026-09-29): copied and exported text becomes CLEAN LINES, and only the two `transcript_export.txt` baseline hashes are re-baselined. This step builds the data model and the export text so the view can be redesigned safely, and moves the guards off the DOM.

## Build
1. `app/static/js/transcript/model.js` (new, add its `<script>` after `core/events.js` and before the engine scripts if events must be caught from the start; check load order): `sf.transcript` with `reset(meta)`, `addChunk({index,startMs,endMs,text,segments})`, `markFailed(index,{startMs,endMs})`, `seedFromRecord(record)`, `get()` (returns `{meta, chunks:[{index,startMs,endMs,status:'done'|'failed', text, segments:[{startMs,endMs,text,avgLogprob}]}], segments:[flat, in absolute time order, plus gap entries for failed chunks]}`), `toText()`, `subscribe(fn)`. Fed ONLY from real data: `sf.events` (`run:start` resets, `chunk:done {index,text,segments}`, `chunk:fail`), and `seedFromRecord` from the stored run (`RunStore.getRun(runId)`: `chunkResults['main-N']` with `status:'done'`, `text`, `segments`) because a resumed run reloads finished chunks from storage WITHOUT emitting `chunk:done` (same trap as T3-b in `status/run-view.js`: see how it seeds the strip). Absolute segment time = `chunk.startMs + Math.round(segment.start * 1000)` (validated in P0: median error 0.01 s). Never invent segments or times.
2. `toText()` format (fixed, tested): for each entry in absolute time order, one paragraph `[HH:MM:SS] <text with surrounding whitespace trimmed>`, paragraphs separated by one blank line, the whole text ending with a single newline. HH:MM:SS = floor of the start time. A failed chunk becomes a paragraph `[HH:MM:SS] (sin texto: este tramo no se pudo transcribir, hasta HH:MM:SS)` so a gap is never hidden in exports. Empty transcript gives an empty string.
3. `copyToClipboard()` and `exportAsFile()` in `js/transcript/view.js` use `sf.transcript.toText()` instead of `#transcript.textContent` (file name and toasts unchanged). The legacy `#transcript` DOM and appender stay as they are for now (T2-b replaces them): do NOT change `createOrderedSegmentAppender` or `appendSegmentToTranscript` (tests pin them). `exportPartialTranscript()` in `status/failures.js` also becomes `toText()` based.
4. Guards: update `tools/ux/transcribe_check.mjs` so `transcript_segments.txt` is `sf.transcript.get().chunks.map(c => c.text).join('\n') + '\n'` (the same chunk texts as today, from the model) and `transcript_export.txt` is `sf.transcript.toText()`; ALSO assert in the script that the legacy DOM `.segment-text` join equals the model chunk-text join (so the DOM and the model cannot diverge). Then re-baseline: regenerate for the 4 min and 12 min fixtures and change ONLY the two `transcript_export.txt` lines in `docs/ux-revamp/baseline/SHA256SUMS`. The `transcript_segments.txt` and `run_artifact.json` lines MUST stay byte-identical to the current ones; if they differ, stop and report (that would mean transcript text changed). Show old and new export hashes in HANDOFF.md. Baseline text directories are gitignored (lecture content): regenerate the local `docs/ux-revamp/baseline/{4min,12min}/transcript_export.txt` too.
