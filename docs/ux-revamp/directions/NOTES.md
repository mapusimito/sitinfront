## Views per direction
start, recording, ready (review the recording, listen, add context, Transcribir), progress, transcript (docked player, search, copy, export, gap), classes, classes-full (storage-full banner), classes-delete (confirmation dialog shown open). Shots of `transcript` and `classes-delete` are viewport captures (sticky toolbar and dock in use, playing segment centred). All other shots are full page, with the docked player and B's bottom bar forced to `position: static` in the capture only (so they appear at the end of the page instead of floating over content).

## Decisions
- Yellow (`--foco`) marks one thing per screen. Transcript screen: the Play/Pause button of the player. Copy and Export are secondary. Search marks are yellow because the brand guide says so.
- The "playing" segment is marked with a left bar and panel background (in `--fg`, not yellow), plus a play icon by the timestamp, plus `aria-current`.
- Timestamps are `<button>`s (keyboard seek). The paragraph text is also clickable for pointer and touch (`.x-seek`), so the 44 px touch target is the text block, while the timestamp button is 28 px high (passes WCAG 2.5.8 at 24 px; brand asks 44). Decide if that is acceptable.
- Title of a class: the context text if given, else the file name or "Grabación del <fecha>". This is a display rule, not a new capability. Needs a user decision.
- A class with a failed chunk is saved and listed as "Incompleta". The audio always plays; the gap marker says the TEXT is missing. Retry is offered where each direction says (A and B in a banner, C in the gap).
- Model summary says "Español · modelo pequeño" (the app default is small). Model help text is only a speed statement ("Un modelo más grande tarda más en transcribir").
- Storage numbers (used/quota) are labelled "estimado" and come from `navigator.storage.estimate()` in the real app. The bar has no percentage.
- Settings: A a details block under the summary, B a summary strip in the header plus a panel on the review screen, C a summary with disclosure on start and a panel on the review screen.
- Cancel copy does not claim instant stop: "el servidor termina el fragmento en curso antes de parar".
- Recording review with audio playback is included (view `ready`) in all three directions.
- The theme control is one icon button that cycles auto, claro, oscuro (label always states the current mode). A menu would be better if explicit choice is wanted.
- Mobile header: the status pill wraps to its own row; "Mis clases" becomes icon only below 40rem.

## Gaps in the shared component set (what the chosen direction needs)
New shared components (prototypes are in `mockup-shared.css`, prefix `x-`):
1. Audio player: transport (play/pause, back 10, forward 10), seek range with mono elapsed and total, speed select (1x, 1,25x, 1,5x, 2x), follow-text toggle (`aria-pressed`). Docked variant (`x-dock`, sticky bottom).
2. Range input styling (tokens only).
3. Sticky find toolbar: search field with icon, count "3 de 27", previous/next, plus actions.
4. Segment additions: timestamp as a button, playing state, click-to-seek text.
5. Header status pill, icon-only theme control, "Mis clases" link.
6. Disclosure summary row (settings summary, "Detalles técnicos") and the technical details block.
7. Saved-class row/card (name, date, duration, size, badge, actions), inline rename, storage meter with note, delete confirmation (uses the existing `sf-dialog`; the mockup shows it open with a scrim).
8. Level meter (exists in `input.css`, lift to shared), file card (exists in `input.css`).
9. Direction-specific: B control bar (sticky top, or bottom on mobile) and bordered table; C chunk spine list with state icons and a two-door start.
Missing icons in the sprite: skip-back/skip-forward (mockups mirror `rotate-cw`), pencil (rename is text only), folder or list. Existing `file-audio` stands in for "Mis clases".
Other gaps: shared banner builder; `sf-progress` is unused because the chunk strip is the honest progress signal.

## Risks and open questions
- Retry of a single failed chunk after the run ends: plan says only if the existing retry code can re-run one chunk; otherwise the button must be "Reintentar todo". Mockups show the single-chunk version.
- Auto-follow pauses on manual scroll: only the toggle is drawn (no separate "paused" state mockup).
- 3-hour transcripts: no virtualization; C's spine has 36 rows and scrolls in the rail. B and A depend on the browser handling a long DOM.
- B on mobile uses about 200 px of 812 for two fixed bars on the transcript screen. C and A use less.
- Brand guide promises 4 h and MP4; the app enforces 500 MB and audio only (copy in mockups says 500 MB, audio).
- Mockup content is invented ("Biología Celular" class); no repo or run text was used.
- Two inline `style` attributes carry a layout number or the `--x-pos` custom property (range fill). No colors or fonts appear outside `tokens.css` (grep-checked).
